D-2026-10-01-live-screen-controls-2 (2026-10-01): One screen, one key. The live key is the screen's display (SoC) address as the bus lists it right after its link opened, never the port string the caller passed: a core use case in `app::screens` connects the chosen screen, then lists it again by identity (like `reopen_screen`: a woken rev C SoC is listed by then) and returns the re-listed screen with its link; its `address()` is the key. `Backend::set_live` (and so the tray's toggle and `restart_screen`'s resume) keys the session, `settings.liveScreen` and the remembered orientation with it; the Studio's reconnect already re-keys by `address()`. `restore_live` replays the saved key and, when it was the MCU port of a listed screen, rewrites `liveScreen` with the display key (the user's settings.json holds `/dev/ttyACM0` today). The passed key is kept only when the screen cannot be listed again. Root cause of the 2026-10-01 report: the UI keys a screen by its SoC (`/dev/ttyACM1`, `ScreenDto.key`), the live session kept the MCU port it was given and every live check compares strings. Decided in auto mode (/jdi-issue).
